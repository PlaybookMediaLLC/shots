This is the implementation and execution ledger for the 60 acceptance criteria in

## Architecture found in the checkout

The attachment predates RFC 024: `social_set` is already canonical, private or
workspace-shared, with stable IDs, versions, per-set scheduling/defaults and a
`channel_connection.socialSetId` association. Extend it; do not add another model.
A private set stays inside its paid workspace and is visible only to its owner.
Teams are existing organizations. Preserve the Go/Ent/Postgres authority and use
Zod contracts → backend SDK → Go services for every browser operation.

The existing share operation changes visibility inside the current workspace;
it does not implement the requested destination/impact/transfer workflow.
Cross-workspace configuration copy is not a transfer. Tenant-bound credentials
must not be reassigned by changing an owner field. Transfer design and tests remain
required, with reauthorization and dependent resource lineage explicitly handled.

Notification receipts now retain explicit read/archive state independently of
immutable activity events and delivery attempts. Personal Slack DMs now use a
separate member-owned connection from workspace channel delivery; local protocol
and browser verification is recorded in the N11 checkpoint below.

Pro/Business/Enterprise remain authoritative. A new workspace begins unsubscribed;
creation itself does not grant paid access. No competitor Agency allowance is
adopted. Existing seats/channels/usage limits apply; any additional set/team limit
must be a centrally defined product decision, not a frontend constant.

## Evidence levels and status

Allowed statuses: **Not started**, **In progress**, **Implemented, unverified**,
**Verified**, **Blocked by external dependency**. Planned tests below do not imply
that test files or results already exist. Unit, protocol fixture, migrated local
integration, real-provider and deployed verification are distinct evidence levels.

The initial audit found existing functionality but has not yet executed the full
acceptance matrix. `npm ci` completed; a separate disposable Postgres container was
created for this task. Customer databases and provider accounts are not test fixtures.

On 2026-10-21 the user confirmed disposable provider accounts are available for
browser authorization. The live Mastodon window reached login, but no provider
account was saved. The user subsequently asked to set Mastodon aside and focus on
the other providers; further Mastodon account checks are deferred. The credential
storage prerequisite now has PostgreSQL, race-detector and non-root container
verification: authenticated encryption, legacy backfill/key rotation, state-bound
custom OAuth secrets and scoped linked-account refresh propagation. These checks
do not mark a provider acceptance criterion complete. Credential-free social
workflow payloads now have local Temporal history/replay proof and stale-account
activity tests; remaining provider flows must be finished before browser handoff.
