Shots is the release-readiness and visual launch platform for software teams. It connects what you ship—releases, pull requests, and production deployments—to cited launch briefs, real product screenshots, on-brand visuals, human approvals, and scheduled publishing.

## Start Here

To set up a live Shots workspace, follow this order:

1. [Getting Started](/docs/getting-started) — understand how workspaces, releases, and approvals fit together.
2. [Workspace Setup](/docs/getting-started/workspace-setup) — configure your product profile, product pages, brand kit, and team roles.
3. [Quickstart](/docs/getting-started/quickstart) — turn your first shipped change into a cited launch brief and branded visuals.
4. [Automate Your Launches](/docs/automate) — watch a GitHub repository or deployment host so future releases draft automatically.
5. [Connect AI Agents](/docs/agents) — give Claude Code, Cursor, Codex, or ChatGPT scoped access over MCP.

## API Reference

Shots exposes authenticated editor utility endpoints (`/api/screenshot`, `/api/export`, `/api/tweet/{id}`, `/api/image-proxy`) and versioned workspace endpoints under `/api/v1`. The interactive reference lives at [/api-reference](/api-reference) and the machine-readable OpenAPI 3.1 contract lives at [/openapi.json](/openapi.json).

## Errors

Every failing HTTP request returns a consistent JSON error envelope containing a stable machine-readable `code`, human-readable `error` and `message`, a recovery `hint`, the HTTP `status`, and a `documentation` link. See [Errors & Idempotency](/docs/api/errors) for the complete status and error code table, including rate-limit (`429`), entitlement (`403`), and quota responses.
